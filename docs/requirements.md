# Нейро-стенографист — требования и условия задания

Источник: презентация «Нейро-стенографист», Nuclear IT Hack, ноябрь 2026. В скобках указаны номера слайдов презентации.

## 1. Формулировка задания (слайд 8)

Разработайте Android-приложение, которое локально преобразует аудиозаписи разговоров в текст, автоматически определяя говорящих и разделяя их реплики.

Приложение должно формировать структурированную расшифровку диалога с указанием участников и временных меток.

Результат должен быть доступен для просмотра в приложении и экспорта в файл. Все этапы обработки должны выполняться непосредственно на Android-устройстве.

## 2. Обязательные требования (слайд 9)

Команда должна разработать приложение, которое:

- работает под управлением Android OS;
- использует локальную LLM;
- импортирует аудиозапись из памяти устройства;
- преобразует речь в текст;
- автоматически определяет и разделяет говорящих;
- формирует временные метки для реплик;
- отображает полученную расшифровку;
- экспортирует результат в файл.

## 3. Ввод и вывод (слайды 14–15)

### 3.1. Входные данные (слайд 14)

Аудиофайл, импортированный пользователем из локального хранилища Android-устройства, либо записанный из интерфейса приложения.

### 3.2. Выходные данные (слайд 14)

Структурированная расшифровка в формате JSON, содержащая:

- текст каждой реплики;
- идентификатор говорящего;
- время начала и окончания реплики.

### 3.3. Формат JSON-вывода (слайд 15)

| Поле | Тип и значение |
| --- | --- |
| `transcript` | `array` — массив реплик |
| `speaker_id` | `string` — ID говорящего |
| `start_ms`, `end_ms` | `integer` — время в мс |
| `text` | `string` — текст реплики |

Пример из презентации:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

## 4. Ограничения обработки (слайды 10–11)

### 4.1. Запрещается (слайд 10)

1. Передавать аудиозаписи внешним сервисам для распознавания.
2. Использовать облачные API для транскрибации, диаризации или обработки текста.
3. Выполнять вычисления на удалённом сервере или компьютере.
4. Подменять работу модели заранее подготовленной расшифровкой.

### 4.2. Условия автономной работы (слайд 11)

- Приложение должно выполнять основную задачу без подключения к интернету.
- Все необходимые модели должны быть доступны на устройстве к моменту проверки.
- Использование готовых моделей и библиотек допускается.

## 5. Ограничения и свобода выбора участников (слайды 12–13)

### 5.1. Подход к использованию ИИ (слайд 12)

- Мы понимаем, что современные решения без вклада ИИ невозможны.
- Мы придерживаемся подхода: ИИ — это ваш инструмент.
- Важно всестороннее и глубокое понимание вашего решения, а не факт его наличия.

### 5.2. Участники самостоятельно определяют (слайд 13)

- модели распознавания речи, диаризации и LLM;
- архитектуру приложения;
- способы интеграции моделей с Android;
- алгоритмы предварительной и последующей обработки аудио;
- подход к определению границ реплик;
- внутренние форматы хранения данных;
- интерфейс пользователя;
- способы повышения производительности и точности.

## 6. Проверка решений (слайд 16)

Работоспособность приложения проверяется экспертами на заранее подготовленных аудиозаписях.

Порядок проверки:

1. Эксперты устанавливают предоставленный заранее APK.
2. Импортируют три тестовые записи диалогов котиков.
3. Запускают транскрибацию и диаризацию.
4. Экспортируют результаты обработки.
5. Сравнивают их с эталонными расшифровками.
6. Рассчитывают показатели точности (WER) и время обработки (RTF).

Все команды проходят проверку на одинаковых тестовых данных.

## 7. Примеры решений в порядке улучшения результата (слайды 17–19)

### 7.1. Базовое (слайд 17)

- работающий Android APK;
- импорт аудиофайла;
- использование локальной LLM;
- распознавание речи;
- автоматическая диаризация;
- временные метки реплик;
- отображение и экспорт результата.

### 7.2. Средний уровень (слайд 18)

Дополнительно могут быть реализованы:

- предварительная обработка аудиосигнала;
- фильтрация пауз и неречевых фрагментов;
- устойчивое определение участников при смене реплик;
- восстановление пунктуации;
- отображение прогресса обработки;
- воспроизведение аудио с переходом к соответствующей реплике.

### 7.3. Ultra Pro Max (слайд 19)

Дополнительно могут быть реализованы:

- обработка фонового шума и некачественных записей;
- распознавание коротких реплик и перебиваний;
- обработка одновременной речи нескольких участников;
- устойчивое распознавание при различиях в тембре и манере речи;
- оптимизация использования оперативной памяти;
- ускорение инференса за счёт аппаратных возможностей устройства;
- редактирование и повторная обработка отдельных фрагментов.
