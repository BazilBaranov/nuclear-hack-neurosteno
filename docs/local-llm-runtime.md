# Локальная LLM и native GPU

`LocalPunctuation` запускает Qwen3.5-0.8B GGUF через llama.cpp в режиме без рассуждений. Модель загружается один раз на стадию и освобождается через `close()`. Контекст ограничен 2048 токенами, вход делится по пробелам на фрагменты до 384 символов, генерация ограничена 384 токенами. Между фрагментами память контекста очищается. Отмена проверяется между батчами prompt и каждым выходным токеном. Весь вызов должен исполняться вне UI-потока.

После генерации `PunctuationGuard` сравнивает последовательность слов, чисел и слов с дефисом. Разрешены регистр и знаки препинания. При добавлении, удалении, перестановке, подмене слов, изменении записи числа, незавершённом ответе или служебном выводе возвращается исходный ASR-текст. Это защита расшифровки, а не доказательство качества расстановки знаков.

## GPU

Android native-библиотека собирается с Vulkan. Для LLM запрашивается размещение всех слоёв на обнаруженном GPU. Неподдерживаемые операции могут оставаться на CPU. При отказе загрузки модели или контекста и при перехватываемой ошибке генерации модель освобождается и загружается на CPU. В диагностике сохраняется бэкенд и причина переключения. Диаризация использует свой [путь Vulkan](nemotron-android.md).

`NativeAcceleration.availableDevices()` показывает доступность backend, а не свидетельство выполнения конкретной стадии. `LocalPunctuation.backendReport` и отчёт Nemotron относятся к реально созданным вычислителям. GGUF/Vulkan не предоставляет универсального NPU-пути. Отдельная интеграция NNAPI/QNN/LiteRT должна проверять совместимость моделей, операторов и драйверов; название Qualcomm/MediaTek/Tensor само по себе ничего не доказывает.

## Сборка и проверки

Нужен современный host `glslc` из Vulkan SDK (NDK r28c включает слишком старый для используемых ggml-шейдеров). На Linux x86_64 запустите `scripts/prepare-vulkan-tools.sh`: скрипт проверяет SHA-256 официального пакета LunarG и распаковывает его только в `artifacts/build/vulkan-tools`, без системной установки. Затем задайте `VULKAN_SDK="$PWD/artifacts/build/vulkan-tools/usr"`. Либо установите `VULKAN_SDK` на свой каталог SDK с `bin/glslc`; CMake скачивает закреплённые Vulkan-Headers и SPIRV-Headers. Для изолированной CPU-проверки native-кода: `-DNEURO_VULKAN=OFF`.

Host smoke test: собрать CMake с `-DNEURO_BUILD_HOST_TESTS=ON -DNEURO_VULKAN=OFF`, target `neuro_llm_smoke`, запустить с путём к проверенному GGUF. Он проверяет реальную генерацию, отмену, CPU-выбор и повторный запрос после очистки контекста. Android JNI/Vulkan и скорость на телефоне проверяются отдельно.


На CPU хоста с Qwen 3.5 проверены SHA-256, пунктуация на коротких примерах на русском и английском, повторный запрос после очистки контекста и отмена. Проверки Qwen 2.5 на устройствах приведены в историческом отчёте [протоколе проверки](VALIDATION.md).

На телефоне отдельный класс `dev.neurostenografist.inference.NativeBackendProbeTest` проверяет Qwen и Nemotron последовательно с запросом CPU и GPU. Нужны модели в `files/models/<bundle.id>/` и речевой PCM16 WAV в `files/validation.wav`. При отсутствии файлов тесты помечаются skipped. Результат записывается в `files/native-backend-probe.json`: backend, фактический выбор GPU, время загрузки/обработки, интервалы говорящих и статус. Перед native-вызовом сохраняется checkpoint, чтобы видеть незавершённую стадию после возможного сбоя vendor driver. `gpuRequested=true` не равнозначно `actualGpu=true`; CPU fallback отмечается отдельно. Для воспроизводимого сравнения нужны одна запись, одинаковые настройки и несколько прогонов с контролем нагрева.
