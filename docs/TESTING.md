Four evidence layers, from cheapest to most expensive. Every claim in the
delivery is tied to one of these; nothing is asserted without one.

## 2. Deterministic evaluation corpus + metrics (host, stdlib-only)

- Corpus: `tests/fixtures/` — 8 synthetic WAV clips, licensed CC0-1.0,
  generated byte-identically by `tests/fixtures/generate_fixtures.py`;
  `SHA256SUMS.txt` pins them. `manifest.json` labels every clip **SYNTHETIC**
  and carries per-file checksum, split purpose (development vs final-check,
  disjoint), language, speaker recurrence, leading silence, overlap and
  segment data. Dev/final names never overlap.
- Metrics: `tests/evaluation/evaluate.py` — WER (insert/delete/substitution,
  normalized text), interval-mapped DER with 150 ms collar for boundary
  tolerance, run-schema validation (integer ms fields enforced), RTF
  aggregation. Self-check: `python3 tests/evaluation/evaluate.py --self-check`.
- Runner: `python3 tests/evaluation/test_evaluate.py` (checksums, WER, DER,
  RTF/schema; prints ALL PASSED or hard-fails).

**Honesty rule**: no real speech transcripts exist for these synthetic clips,
so WER on them is meaningless and is never reported. The corpus exists to
exercise the metric plumbing deterministically and to bound the final-check
procedures; accuracy numbers require a measured, human-authored reference run.

## 3. Instrumentation acceptance (on-device, real runtime)

`app/src/androidTest/java/dev/neurostenografist/acceptance/`:

- `ModelStoreAcceptanceTest` — real asset extraction + SHA-256 verification of
  all shipped bundles, tamper detection (`isReady` flips false), repair by
  reinstall, no temp-dir leftovers. Prints measured extract times per bundle.
- `PipelineAcceptanceTest` — real sherpa engines end-to-end:
  RU/EN tone clips through the full pipeline (schema-gated `CompletedRun`,
  always-present uncalibrated-clustering warning, JSON export round-trip,
  integer-ms contract), an unsupported-tone clip (must fail loudly with a
  named stage or complete only with honest empty/warning output), and a
  silence clip (must never silently produce a fake transcript). Gates are
  structural; latency is *measured and printed* (wallMs + stageMs), never
  asserted against a fabricated threshold.

  Timing-test seam limits: `stageMs` is captured with real engines on the
  device, so timing numbers are hardware-specific observations, not
  reproducible gates — they must not be compared across runs or expected from
  unit tests (the JVM seam uses fakes and asserts only ordering/counts, not
  durations).
- `PersistenceAcceptanceTest` — real file-backed RunStore lifecycle
  (created → running → completed; process-death → interrupted recovery),
  SourceStore upsert/list/delete round-trip, TranscriptJson export contract,
  SettingsStore validation (unsupported sample rate rejected).

## 4. Delivery verification (host, at hand-off)

`./scripts/verify-delivery.sh app/build/outputs/apk/debug/app-debug.apk` —
APK SHA-256/size, bundled ABI list (`lib/*/*.so` across the four sherpa ABIs),
source content fingerprint + dirty state (`scripts/source-fingerprint.sh`
hashes the working-tree bytes of all relevant source/build/config files,
staged+unstaged+relevant untracked together; caches/build outputs/`artifacts/`
and `.git` excluded), reference git revision, pinned-AAR hash presence,
fixture-integrity check; writes `artifacts/delivery-summary.env`. Hard-fails
on any mismatch.

**Provenance rule**: the fingerprint names the delivered source bytes but does
NOT prove the supplied APK was built from them. Provenance is established by
rebuilding exactly that snapshot (`scripts/build.sh`) and re-running this
script so APK and fingerprint come from the same tree. The final rebuild +
metadata regeneration happen after all delivery lanes integrate; until then,
apk-vs-source identity must stay unclaimed.

CI (`.gitlab-ci.yml`): SAST + Secret Detection plus real build stages
(`verify_unit`, `verify_lint`) that provision the pinned AAR first and fail
hard on a missing SDK/JDK — a partially cached runner can never go green.
