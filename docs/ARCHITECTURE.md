# Архитектура Android-приложения

Корневой пакет — `dev.neurostenografist`. Интерфейс построен на Jetpack Compose и переведён на русский язык. Расшифровка, разделение говорящих, обработка звука и пунктуация выполняются локально. Сеть используется для предварительной загрузки моделей; голосовые записи не отправляются сервису распознавания.

## Слои

| Каталог / компонент | Назначение |
| --- | --- |
| `core/` | Реплики, интервалы говорящих, состояния запусков, выбор модели и исходная временная шкала. |
| `audio/` | Запись, WAV/MediaCodec декодирование, потоковое преобразование в 16 кГц mono, нормализация аудио. |
| `inference/` | Оркестрация, каталог и проверка моделей, ASR/LID, диаризация, GTCRN, VoxLock, локальная LLM, выбор вычислителей. |
| `data/` | JSON-хранилища источников, настроек и запусков; атомарное сохранение результата и пользовательских исправлений. |
| `ui/` | Запись/импорт, список запусков, модели, настройки, редактирование и воспроизведение реплик. |
| `ProcessingService` | Foreground service: выполняет обработку вне главного потока и публикует прогресс. |
| `RecordingService` | Foreground service для микрофона и записи. |
| `AppGraph` | Общие хранилища процесса, уведомления, отмена и восстановление состояния после остановки процесса. |

## Порядок обработки

1. **Декодирование.** WAV PCM16 разбирается напрямую, поддерживаемые сжатые контейнеры — через Android MediaCodec. Вход преобразуется блоками; сохраняется итоговый mono PCM 16 кГц. Ограничение длительности и памяти проверяется до чрезмерного выделения heap.
2. **Подготовка звука.** Базовая обработка звука сохраняет исходную временную шкалу. Если включено подавление шума, затем применяется GTCRN.
3. **Диаризация всей записи.** Выбранная Nemotron-3-Diarization либо Pyannote segmentation + TitaNet выделяет интервалы говорящих. Состояние Nemotron сохраняется между порциями одной записи. После стадии native-ресурсы освобождаются.
4. **Определение языка.** В режиме «Авто» Whisper tiny определяет язык по речевым окнам. Неоднозначность или неподдерживаемый язык дают ошибку, подтверждённое отсутствие речи — пустой результат. При ручном выборе русского или английского стадия пропускается.
5. **Выбор ASR.** Ручной выбор должен соответствовать языку и установленным весам. Автоматический выбор использует только готовые проверенные bundles; для русского приоритет начинается с GigaAM-v3 RNNT, для английского — Whisper base. Это эвристика каталога, а не таблица измеренного качества.
6. **Одновременная речь.** Если включено разделение, VoxLock использует чистые образцы голосов из этой же записи. Если разделение выключено или образцов недостаточно, спорный интервал получает одного владельца, а в результате появляется предупреждение.
7. **ASR реплик.** Один recognizer на стадию обрабатывает фрагменты до 25 секунд. Длинные реплики делятся по исходной шкале; поток и recognizer освобождаются в `finally`.
8. **Пунктуация.** Если функция включена, после освобождения ASR и изоляции загружается Qwen3.5-0.8B Q4_K_M через llama.cpp. `PunctuationGuard` разрешает изменение регистра и знаков препинания. При изменении слов или чисел и при обрезанной генерации сохраняется исходный текст. Таймкоды и speaker ID берутся из предыдущих стадий.
9. **Сохранение.** `CompletedRun` хранит реплики, реально использованные model ID / SHA-256, время стадий и диагностические сообщения. Экспорт JSON сохраняет `speaker_id`, `start_ms`, `end_ms`, `text`, с целыми миллисекундами.

## Модели и автономность

Большие веса не упакованы в APK. `ModelStore` загружает файлы из источников `ModelCatalog`, проверяет ожидаемые размер и SHA-256, затем атомарно заменяет каталог bundle в `files/models/<bundle.id>/`. Частично скачанный набор не считается готовым. Большинство URL закреплены конкретной ревизией; для release-артефактов контроль неизменности обеспечивается также ожидаемым SHA-256. Старый Zipformer без доступного пофайлового источника работает только из ранее установленной копии.

После загрузки необходимых моделей весь цикл работает без сети. Микрофон и выбранные пользователем файлы обрабатываются в приложении. Временные файлы изоляции находятся в приватном cache. Пользователь может удалить модели и сохранённые результаты отдельно.

## Вычислители

- CPU: ограниченное число рабочих потоков (до четырёх, с резервом для Android/UI).
- GGUF: Qwen использует CPU/Vulkan; на проверенном Honor 200 по умолчанию CPU из-за ошибки драйвера. Nemotron по умолчанию запрашивает исправленный Vulkan-путь на Pixel 9 Pro. При перехватываемом отказе используется CPU, а результат содержит отчёт о выбранном бэкенде.
- ONNX: sherpa-onnx с NNAPI в arm64-сборке. Инвентаризация Android-драйверов определяет возможность запросить аппаратный provider. ORT может исполнить неподдержанные узлы на CPU. Диагностическое профилирование считает фактические исполнения узлов NNAPI/CPU; без профиля приложение не утверждает использование NPU.

Марка Snapdragon, MediaTek или Google Tensor не служит доказательством доступности/скорости NPU. Сравнение устройств и измеренные результаты ведутся в [протоколе проверки](VALIDATION.md); описание native LLM и сборки — в [local-llm-runtime.md](local-llm-runtime.md).

## Интерфейс и жизненный цикл

Тяжёлая обработка выполняется в background dispatcher. Списки реплик ленивые; воспроизведение работает по исходным границам выбранной реплики. Пользователь может исправить текст и имя говорящего либо повторно распознать одну реплику. Повторный запуск заменяет старый текст только после успешной обработки; ошибки и отмена сохраняют прежний результат. При смерти процесса незавершённые запуски переводятся в прерванные.

Отмена проверяется между стадиями/фрагментами; в LLM — также между decode-батчами и токенами. Уже выполняющийся вызов стороннего runtime может завершиться до обработки отмены.

## Проверки

JVM-тесты проверяют временную шкалу, модельный выбор, обработку аудио, сохранение/исправления и защиту текста. Host C++ smoke использует реальные веса Qwen. Android instrumentation содержит acceptance-пробы, native CPU/GPU сравнение на одной записи, диагностическое профилирование NNAPI и нагрузку интерфейса длинным списком реплик. Наличие теста или успешная компиляция не означает успешный запуск на телефоне: фактический статус и артефакты собраны в [протоколе проверки](VALIDATION.md).
