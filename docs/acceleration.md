# Аппаратное исполнение в v0.2

Выбор бэкенда зависит от версии Android и формата установленных весов. В разделе «Модели» на Android 14+ видны дополнительные пакеты LiteRT. Установите также основную модель. Она нужна для повторной обработки на CPU, если драйвер или дополнительный граф выдаст ошибку.

| Стадия | Android 14+ | Android 9–13 |
| --- | --- | --- |
| Whisper tiny, включая автоопределение языка | Энкодер LiteRT GPU, декодер ONNX CPU. Без дополнительных весов или при ошибке используется исходный Whisper tiny на CPU. | NNAPI для совместимых ONNX-операций, остальные на CPU. |
| Pyannote | Готовый гибрид Pyannote 3.0 / WeSpeaker использует ONNX CPU для сегментации и LiteRT GPU для эмбеддингов. Для фолбека используется Pyannote / TitaNet на CPU. | NNAPI для совместимых операций Pyannote / TitaNet. |
| Nemotron 3 | Два графа LiteRT GPU. Если пакет недоступен или его запуск завершается ошибкой, приложение пробует GGUF через Vulkan и при перехватываемой ошибке повторяет на CPU. | GGUF на CPU. |
| Qwen 3.5 | LiteRT-LM GPU при наличии дополнительных весов. Исходный GGUF через llama.cpp на CPU при отсутствии пакета или ошибке LiteRT-LM. | GGUF на CPU. |
| GigaAM-v3, Whisper base/small, Zipformer | ONNX CPU. Для этих графов в сборке доступны CPU и NNAPI, а NNAPI на Android 14+ отключён. | NNAPI для совместимых ONNX-операций. У GigaAM только часть энкодера может уйти в NNAPI. |

GTCRN и VoxLock работают на CPU. Дополнительные пакеты содержат готовые публикации авторов экспортов. Сборка приложения не конвертирует веса. Встроены только вычислители и небольшие таблицы для подготовки звуковых признаков. [Whisper tiny](https://github.com/john-rocky/LiteRT-Models/tree/f9f73d14abc4a58990aaa3e599d0b48a5982bb37/whisper) · [Nemotron 3](https://huggingface.co/litert-community/Nemotron-3-Diarization-LiteRT) · [Pyannote / WeSpeaker](https://huggingface.co/litert-community/Speaker-Diarization-LiteRT) · [Qwen 3.5](https://huggingface.co/litert-community/Qwen3.5-0.8B)

NNAPI доступен для обеих поддерживаемых ABI. На Android 10–13 приложение проверяет наличие аппаратного драйвера и использует CPU при его отсутствии. Android 9 позволяет запросить NNAPI без предварительного перечисления устройств. Отчёт ORT по узлам показывает, исполнялась ли часть графа через NNAPI.

GigaAM ждёт подготовку NNAPI до 1,5 секунды. Если драйверу нужно больше времени, текущая запись распознаётся на CPU, а одна сессия готовится в фоне. Следующая обработка может переиспользовать её. Готовая сессия освобождается через 45 секунд простоя. Это ограничивает ожидание приложения. Время компиляции графа в драйвере зависит от устройства.

В «Подробностях обработки» сохраняются выбранные бэкенды и причины перехватываемых переходов на CPU. Для подтверждения аппаратного исполнения используйте диагностику `OnnxBackendProbeTest` или `LiteRtBackendProbeTest`.
